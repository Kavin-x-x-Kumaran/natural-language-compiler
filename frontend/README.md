# Natural language compiler — frontend

React + Vite frontend for a natural-language → C compiler. You write one
instruction per line, press **Run** to get C11 source back, then **Compile &
Run** to execute it with an interactive terminal.

> **The backend does not exist yet.** Everything in this app that talks to a
> server is written against an *anticipated* contract (a proposal from the
> frontend side). Nothing here compiles or runs C — that is entirely the
> backend's job, sandboxing included.

## Setup

```bash
cd frontend
npm install
cp .env.example .env     # optional; the defaults below are only placeholders
npm run dev              # http://localhost:5173
```

Other scripts:

| command | what it does |
| --- | --- |
| `npm run dev` | dev server |
| `npm run build` | production build into `dist/` |
| `npm run preview` | serve the production build |
| `npm test` | Vitest unit tests (`buildPayload`, `terminalReducer`) |

There is no `lint` script and no ESLint dependency — the project deliberately
keeps its dependency list to React, Vite, `lucide-react` and Vitest.

## Environment variables

Copy `.env.example` to `.env`. These are **placeholders**; setting them does not
mean a server is listening.

```
VITE_API_BASE_URL=http://127.0.0.1:8000
VITE_WS_BASE_URL=ws://127.0.0.1:8000
VITE_ENABLE_MOCK=false
```

If `VITE_API_BASE_URL` is empty and mock mode is off, Run fails immediately with
"Backend URL is not configured." and sends no request.

## Anticipated backend contract (frontend proposal)

Not implemented anywhere, not agreed with a backend. It lives in
`src/services/endpoints.js`, `api.js` and `websocket.js`, so aligning with the
real backend should mean editing only those three files.

### Generation — HTTP

`POST {VITE_API_BASE_URL}/compile` with `Content-Type: application/json`.

Request body: a top-level array (the backend joins the lines and appends
them to `prefix.txt` before calling the model):

```json
[
   { "line": 1, "text": "Read 2 numbers as input" },
   { "line": 2, "text": "Add them" },
   { "line": 3, "text": "Display the answer" }
]
```

Anticipated responses:

| case | shape | frontend behaviour |
| --- | --- | --- |
| 2xx | `{ "code": "<string>" }` | `code` is used verbatim |
| `code` starts with `ERROR:` | e.g. `ERROR: INVALID_INPUT \| …` | shown as a terminal error; the C editor is **not** touched |
| non-2xx | `{ "error": "…" }` optional | `HTTP <status> — <error or statusText>` |
| 2xx, not JSON or no string `code` | — | "Unexpected response format from backend." Nothing is guessed. |
| transport failure / timeout | — | "Could not reach the backend." / "The request timed out after 120 seconds." |

### Execution — WebSocket

`{VITE_WS_BASE_URL}/ws/run`. **This message shape is a proposal**, to be aligned
with the real backend.

Client → server:

```json
{ "type": "start", "source": "<C source>" }
{ "type": "stdin", "data": "10 20\n" }
{ "type": "stop" }
```

Server → client:

```json
{ "type": "status", "state": "compiling" | "running" }
{ "type": "stdout", "data": "..." }
{ "type": "stderr", "data": "..." }
{ "type": "input_required" }
{ "type": "exit", "code": 0, "phase": "compile" | "run" }
{ "type": "error", "message": "..." }
```

Malformed frames are ignored; at most one "Received an unreadable message from
the server." is shown per run. Sockets are closed on a new run in the same tab,
tab close, unmount and the stop timeout. Every event is tagged with its tab and
session id, so a finished run can never write into a newer one.

## Mock mode

Development only, off by default. Set `VITE_ENABLE_MOCK=true` and restart the
dev server. Then:

- the status chip shows an amber **Mock mode** at all times,
- a thin amber banner sits under the header,
- every simulated status line is prefixed `[mock]`,
- generation returns a placeholder program whose first line is
  `/* MOCK OUTPUT: not generated by the model */`,
- execution simulates compiling → running → a prompt → `input_required` → a
  fake echo → exit 0, and honours Stop.

Nothing in `src/services/mock.js` can run while the flag is false.

## Keyboard shortcuts

| shortcut | action |
| --- | --- |
| `Ctrl/⌘ + Enter` | Run (generate C code) |
| `Ctrl/⌘ + S` | save this tab to localStorage now ("Saved" flashes for 1.5s) |
| `Alt + N` | new tab |
| `Alt + W` | close the current tab (with the usual confirmation) |
| `Escape` | close the open dialog and return focus to what opened it |

**Limitation:** `Ctrl+T` and `Ctrl+W` are reserved by browsers and cannot be
intercepted reliably, so they are **not bound at all**. The `Alt` variants above
are used instead, and only the working shortcuts appear in the hint bar.

Shortcuts never fire while you are typing in the tab-rename field or the
terminal input; `Escape` there cancels the rename / blurs the input.

## Architecture

```
src/
  App.jsx                  workspace layout + wiring
  components/              presentation and interaction only
  hooks/
    useWorkspace.js        tabs, active tab, persistence
    useCompiler.js         generation + execution state machine, per tab
    useShortcuts.js        one global keydown listener
  services/                endpoints.js, api.js, websocket.js, mock.js (no React)
  utils/                   buildPayload, terminalReducer, stripAnsi, storage, constants
  styles/global.css        all design tokens as CSS variables
```

## Security notes

- Generated C and all terminal text are treated as plain text: no `eval`, no
  `Function`, no `dangerouslySetInnerHTML`. ANSI escapes are stripped.
- The frontend does **not** sandbox anything. Compiling and executing untrusted
  C safely is entirely the backend's responsibility.
- No credentials or secrets live in the frontend.

## Assumptions

Choices made where the specification left something open:

1. **Project location.** The repository root already held `backend/`, so the app
   lives in `frontend/` rather than at the root.
2. **Payload lines.** Blank lines are skipped, and `line` is the 1-based number
   shown in the gutter — so the numbers can have gaps.
3. **Whitespace.** Only trailing whitespace is trimmed; leading indentation is
   preserved.
4. **Limits.** `MAX_LINES = 1000`, `REQUEST_TIMEOUT_MS = 120000`,
   `WS_CONNECT_TIMEOUT_MS = 10000`, `STOP_TIMEOUT_MS = 5000`,
   `MAX_TERMINAL_ENTRIES = 5000`, 10 tabs maximum.
5. **Placeholder paths.** `/compile` and `/ws/run`.
6. **`ERROR:` rule.** A 2xx `code` beginning with `ERROR:` is a rejection: it
   is shown as a terminal error and never reaches the C editor.
7. **Connection status.** Derived only from real calls. Nothing is pinged on
   load (there is no health endpoint), so the chip starts grey.
8. **Not persisted.** Terminal output, execution state and input drafts are
   rebuilt empty on every load; only `id`, `name`, `nlText`, `cCode`, `cEdited`
   and the active tab id are stored, under `nlc.workspace.v1`.
9. **Monaco.** Not a dependency of this project, so both editors use the shared
   `LineEditor` textarea, as specified.
10. **First-word emphasis** in the natural-language editor (the optional
    nicety) was dropped: a transparent textarea over a `<pre>` overlay could not
    be kept pixel-aligned across scrolling and horizontal overflow, and the
    specification says to remove it rather than ship near-alignment.
11. **Empty C editor.** The "Generated C code appears here after you press Run."
    message is the textarea's placeholder, so the editor stays typeable before
    anything has been generated.
12. **Merging.** Only consecutive `stdout`/`stderr` chunks are merged into one
    entry. Status, stdin and error entries always stay separate.
13. **Contrast.** Every text colour meets WCAG AA on the glass panes (body
    12.4:1, muted 7.6:1, red 7.1:1, amber 11.7:1, white-on-blue 5.2:1). The one
    exception is the gutter line numbers, whose colour `#52525B` is fixed by the
    design specification and sits at 2.4:1 — it is a non-essential repetition of
    position, but raising `--gutter` to `#7A7A85` would clear AA if you want it
    to.
14. **Autosave.** Debounced by 300ms, so a change made and immediately followed
    by a reload within that window is not stored. `Ctrl/⌘ + S` saves at once.
