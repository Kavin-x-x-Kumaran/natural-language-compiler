# Natural language compiler — frontend

React + Vite web UI. You write one instruction per line, press **Run** to get
C11 source from the model, then **Compile & Run** to build it with gcc and use
it in an interactive terminal.

## Running it

From the **repository root**, run `npm run dev`. It starts the backend and this
frontend together; see the [root README](../README.md).

To run only the frontend (with the backend already running separately):

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173
```

| command | what it does |
| --- | --- |
| `npm run dev` | development server |
| `npm run build` | production build into `dist/` |
| `npm run preview` | serve the production build |
| `npm test` | Vitest unit tests (`buildPayload`, `terminalReducer`) |

## Settings (optional)

No `.env` file is needed: the frontend talks to the backend at
`http://127.0.0.1:8000`. Copy `.env.example` to `.env` only if the backend runs
somewhere else.

| variable | default | meaning |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `http://127.0.0.1:8000` | backend HTTP address |
| `VITE_WS_BASE_URL` | `ws://127.0.0.1:8000` | backend WebSocket address |
| `VITE_ENABLE_MOCK` | `false` | simulate everything in the browser (see below) |

## How it talks to the backend

All URLs and message shapes live in `src/services/` (`endpoints.js`, `api.js`,
`websocket.js`). The backend side is documented in
[`backend/README.md`](../backend/README.md).

- `GET /health` every 10 seconds sets the header chip: **Ready**, **AI model not
  running** (Compile & Run still works), or **Backend not running**.
- `POST /compile` with `[{ "line": 1, "text": "..." }, ...]` returns
  `{ "code": "..." }`. An answer starting with `ERROR:` is the model refusing:
  it is shown as an error, never put in the editor. Failures carry
  `{ "error": "..." }`, which is shown as-is. The browser waits up to 5 minutes.
- `WS /ws/run` compiles and runs the program, streaming output and asking for
  input when the program waits for it.

## Mock mode

Development only, off by default. Set `VITE_ENABLE_MOCK=true` in `frontend/.env`
and restart. The chip then shows an amber **Mock mode**, a banner sits under the
header, every simulated line is prefixed `[mock]`, and the "generated" program
starts with `/* MOCK OUTPUT: not generated by the model */`. Nothing in
`src/services/mock.js` runs while the flag is false.

## Keyboard shortcuts

| shortcut | action |
| --- | --- |
| `Ctrl/⌘ + Enter` | Run (generate C code) |
| `Ctrl/⌘ + S` | save this tab now ("Saved" flashes for 1.5s) |
| `Alt + N` | new tab |
| `Alt + W` | close the current tab (with the usual confirmation) |
| `Escape` | close the open dialog |

`Ctrl+T` and `Ctrl+W` belong to the browser, so the `Alt` variants are used
instead. Shortcuts never fire while you type in the tab-rename field or the
program-input box.

## Architecture

```
src/
  App.jsx                  workspace layout + wiring
  components/              presentation and interaction only
  hooks/
    useWorkspace.js        tabs, active tab, saving to localStorage
    useCompiler.js         generation + execution state machine, per tab
    useShortcuts.js        one global keydown listener
  services/                endpoints.js, api.js, websocket.js, mock.js (no React)
  utils/                   buildPayload, terminalReducer, stripAnsi, storage, constants
  styles/global.css        all design tokens as CSS variables
```

Tabs (their names, English text and C code) are saved in the browser's
localStorage; terminal output is not.

## Security notes

- Generated C and all terminal text are treated as plain text: no `eval`, no
  `Function`, no `dangerouslySetInnerHTML`. ANSI escapes are stripped.
- The frontend does not sandbox anything. Running untrusted C safely is the
  backend's job; see its security section.
- No credentials or secrets live in the frontend.
